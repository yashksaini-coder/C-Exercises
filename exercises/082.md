# 082 — Reading until EOF

Implement `size_t count_lines(FILE *stream)` in `082.c`.

Read `stream` from its current position to end-of-file with `fgetc` and
return the number of lines: the number of `'\n'` characters, **plus one
if the last character read was not `'\n'`** (a final line without a
terminator still counts). An empty stream → `0`.

`fgetc` returns an `int`, not a `char`: it yields every byte `0`–`255`
*and* the distinct value `EOF` (−1). Store the result in an `int` and loop
`while ((c = fgetc(stream)) != EOF)`. Storing it in a `char` first is the
classic bug: on platforms where `char` is unsigned, `EOF` becomes `255`
and the loop never ends; where it is signed, a real byte `0xFF` is
mistaken for `EOF` and the count stops early. The test includes a `0xFF`
byte to catch exactly that.

Do not use `fgets` (it needs a maximum line length), `getline` (POSIX
only), or `fread` into a buffer; the exercise is the single-character
loop. Do not rewind or close the stream.

The tests use `tmpfile()`, write content, `rewind`, call `count_lines`,
and `fclose`.

Examples: `"a\nb\nc\n"` → `3`; `"a\nb"` → `2`; `""` → `0`; `"\n"` → `1`;
`"\n\n"` → `2`; `"x\xFFy\n"` → `1`.
