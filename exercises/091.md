# 091 — CIDR masks

Implement `bool ipv4_in_subnet(const uint8_t address[4], const uint8_t network[4], unsigned prefix_length)`
in `091.c`.

A subnet in CIDR notation, `10.0.0.0/8`, is a network address plus a prefix
length: the number of leading bits that must match. Return `true` when the
first `prefix_length` bits of `address` equal the first `prefix_length` bits
of `network`. Bits past the prefix are ignored, so the caller may pass a
host address as `network` (`10.1.2.3/8` means the same as `10.0.0.0/8`).
`prefix_length` is `0` through `32`; `/0` matches every address and `/32`
matches only the exact address. Return `false` for a `prefix_length` above
32.

Pack each 4-byte array into a `uint32_t` (first byte most significant, like
exercise 055), build the mask, and compare `(a & mask) == (n & mask)`.

The trap: the obvious mask `~0u << (32 - prefix_length)` evaluates
`~0u << 32` for `/0`, and shifting a 32-bit value by 32 is undefined
behaviour in C (on x86 it silently yields the unshifted value, so the bug
only shows up on another machine). Handle `/0` explicitly, or compute the
mask from a 64-bit value: `(uint32_t)(0xFFFFFFFFull << (32 - prefix_length))`,
or `prefix_length == 0 ? 0 : ~0u << (32 - prefix_length)`. Run the sanitized
build (`SANITIZE=1`): UBSan reports the bad shift.

No library helpers are needed; `inet_pton` and friends are not allowed.

Examples: `ipv4_in_subnet({10, 1, 2, 3}, {10, 0, 0, 0}, 8)` → `true`;
`ipv4_in_subnet({192, 168, 1, 10}, {192, 168, 0, 0}, 16)` → `true`;
`ipv4_in_subnet({192, 169, 1, 10}, {192, 168, 0, 0}, 16)` → `false`;
`ipv4_in_subnet({1, 2, 3, 4}, {200, 200, 200, 200}, 0)` → `true`;
`ipv4_in_subnet({1, 2, 3, 4}, {1, 2, 3, 5}, 32)` → `false`;
`ipv4_in_subnet({1, 2, 3, 4}, {1, 2, 3, 5}, 31)` → `true`.
