# 081 — File I/O

Implement `int copy_file(const char *source_path, const char *destination_path)`
in `081.c`.

Copy the bytes of the file at `source_path` into a new file at
`destination_path` (created or truncated), using only `<stdio.h>`:
`fopen`, `fread`, `fwrite`, `fclose`. Open both files in **binary** mode
(`"rb"`, `"wb"`): on POSIX the `b` is a no-op, on Windows it stops the
library translating newlines and treating `0x1A` as end-of-file — and the
test copies bytes `0x00` and `0xFF`, which text mode may mangle.

Copy through a `4096`-byte local buffer in a loop: `fread` up to the
buffer size, `fwrite` exactly the number of bytes read, until `fread`
returns `0`. Do not read the file into one allocation (it may be larger
than memory) and do not go byte by byte with `fgetc` (slow).

Return `0` on success, `-1` if either file cannot be opened, if a read
error occurs (`ferror` after the loop), or if a write comes up short. On
every exit path close whatever you opened: a function with two `FILE *`
and several failure points is where `goto cleanup` (088) starts to pay
off, but nested `if`s are fine here. An empty source produces an empty
destination and returns `0`.

The tests create files under `build/` with `mkstemp` and remove them
afterwards; do not use `tmpnam`.

Examples: a 7-byte text file → identical copy; a 10 000-byte file (more
than one buffer) containing `0x00` and `0xFF` → identical copy; empty file
→ empty copy, returns `0`; a missing source → `-1`.

> [!TIP]
> Read: Beej's Guide to C, §9.6 Binary File I/O —
> https://beej.us/guide/bgc/html/split/file-inputoutput.html
> `cp` in 25 lines is a common "show me you can use stdio correctly" task;
> the points are the loop termination and the error paths.

Run `make run N=81`; check with `make test N=81`.
