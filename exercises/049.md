# 049 — String builder with ownership

Implement `int sb_append(StringBuilder *sb, const char *s)` and
`char *sb_finish(StringBuilder *sb)` in `049.c`.

`StringBuilder` is `typedef struct { char *data; size_t length, capacity; } StringBuilder;`.
A zeroed builder (`StringBuilder sb = {0};`) is valid and empty. Invariant
after every successful `sb_append`: `data` is NUL-terminated at `length`,
and `capacity` counts bytes including room for that NUL, so
`length + 1 <= capacity`.

- `sb_append` appends `s` to the buffer, growing `capacity` by doubling
  (start at 16 or `strlen(s) + 1`, whichever is larger; keep doubling until
  `length + strlen(s) + 1` fits) with `realloc` into a temporary pointer.
  Return `0` on success, `-1` on allocation failure or `NULL` arguments; on
  failure the builder is unchanged. Appending `""` succeeds and changes
  nothing visible (it may allocate).
- `sb_finish` hands ownership of the buffer to the caller and resets the
  builder to `{0}` so it can be reused. The returned string is `data`
  itself (optionally shrunk with `realloc(data, length + 1)`); the caller
  frees it. Finishing an empty builder — one that never allocated — must
  still return an allocated `""`, not `NULL`. Return `NULL` only on `NULL`
  input.

The lesson is *ownership transfer*: after `sb_finish`, the builder no
longer refers to the buffer, so there is exactly one owner and no double
free. Compare `OwnedString` (040) and `vector_free` (043).

Allowed: `malloc`, `realloc`, `strlen`, `memcpy`. Forbidden: `strcat` in
a loop over a fixed buffer (quadratic and truncating).

Examples: append `"foo"`, `"bar"`, `"!"` → `sb_finish` returns `"foobar!"`
with the builder back to `{data=NULL, length=0, capacity=0}`; finish on a
fresh builder → `""`; after `sb_finish`, appending `"again"` and finishing
again → `"again"` (reuse works); 1000 appends of `"ab"` → a 2000-character
string.
