# 088 — goto cleanup and ownership

Implement `int load_config(const char *path, Config *out)` and
`void config_free(Config *config)` in `088.c`.

`typedef struct { char *name; char *value; int *numbers; size_t number_count; } Config;`

The file at `path` is a text file of lines in any order, at most one of
each key, with no spaces around `=`:

```
name=<string>
value=<string>
numbers=<int>,<int>,...
```

Blank lines are skipped. `name` and `value` are copied into freshly
allocated strings (everything after the `=` up to the newline, which may
be empty). `numbers` is parsed with `strtol` into a freshly allocated
`int` array of `number_count` elements; the list must be non-empty, each
item must be a complete integer with no surrounding spaces (`1,x`,
`1,,2`, `1, 2` and a trailing comma are malformed — note that `strtol`
skips leading whitespace on its own, so check the first character
yourself). A key that is absent leaves its field `NULL` (or `0`).

Return `0` on success with `*out` filled in. Return `-1` and leave `*out`
**fully zeroed** on **any** failure: the file cannot be opened, a line has
no `=`, an unknown key, a duplicate key, a bad number, a line longer than
255 characters, or a failed allocation. Whatever was allocated before the
failure must be freed.

That last rule is the exercise. A function with several resources and
many failure points needs one exit path that releases everything. The
idiom:

```c
int load_config(const char *path, Config *out) {
    int status = -1;
    FILE *f = NULL;
    *out = (Config){0};          /* every pointer starts NULL so free() is safe */
    f = fopen(path, "r");
    if (!f) goto fail;
    while (fgets(line, sizeof line, f)) {
        ...
        if (bad) goto fail;
    }
    status = 0;
    goto done;                    /* or: fclose(f); return 0; */
fail:
    config_free(out);             /* frees whatever is non-NULL, zeroes *out */
done:
    if (f) fclose(f);
    return status;
}
```

`goto` forward to a label at the end of the function is the one use of
`goto` that is idiomatic C (the Linux kernel is full of it); it replaces
deeply nested `if`s or duplicated `free` calls on each path. The rule
that makes it safe: initialise every resource to a "nothing to free" state
(`NULL`) *before* the first `goto`, and never jump backwards or into a
block.

`config_free(c)` frees `name`, `value`, `numbers` and zeroes the struct;
calling it twice, or on a zeroed struct, is safe. Use `fopen`, `fgets`,
`strtol`, `strchr`, `strcmp`, `malloc`/`free`; `strdup` is allowed for
the strings.

The tests write files under `build/` with `mkstemp` and run with
`SANITIZE=1`, so a leak on the malformed-file path is a failure.

Examples: file `name=demo\nvalue=hello world\nnumbers=1,2,3\n` → `name
"demo"`, `value "hello world"`, `numbers {1, 2, 3}`, count `3`; file
`numbers=42\n` → `name NULL`, `value NULL`, one number; file
`name=x\nnumbers=1,oops\n` → `-1`, `*out` zeroed, nothing leaked;
missing file → `-1`.
