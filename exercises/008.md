# 008 — Detect signed overflow safely

Implement `bool add_overflows(int a, int b)` in `008.c`.

Return `true` when `a + b` cannot be represented as an `int`, i.e. the
mathematical sum is greater than `INT_MAX` or less than `INT_MIN`. Return
`false` otherwise.

You must decide *without performing the addition*. Signed integer overflow
is undefined behaviour in C: `a + b` with overflowing operands is not
"wraps around", it is "the compiler may assume this never happens", and
`if (a + b < a)` is routinely optimised away. `make test N=8 SANITIZE=1`
reports the overflow the moment you compute it. Instead compare against the
limits from `<limits.h>` before adding:

- if `b > 0`, overflow iff `a > INT_MAX - b`;
- if `b < 0`, overflow iff `a < INT_MIN - b`;
- if `b == 0`, never.

Both subtractions are safe because `b` has the right sign to pull the limit
toward zero. No `long long` widening, no builtins (`__builtin_add_overflow`),
no casts to unsigned: the point is the limit comparison.

Examples: `add_overflows(1, 2)` → `false`; `add_overflows(INT_MAX, 1)` →
`true`; `add_overflows(INT_MIN, -1)` → `true`; `add_overflows(INT_MAX, INT_MIN)`
→ `false`; `add_overflows(INT_MAX, 0)` → `false`.
