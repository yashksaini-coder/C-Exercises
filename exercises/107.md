# 107 — Run-once initialization

Implement `int once_init_value(void)` in `107.c`.

Lazy initialisation that many threads may trigger at the same time must
run exactly once. The naive `if (!initialised) { init(); initialised = 1; }`
lets two threads both see `initialised == 0` and both run `init()`. POSIX
provides `pthread_once` for this: a `static pthread_once_t control =
PTHREAD_ONCE_INIT;` and `pthread_once(&control, init_function)`; the first
caller runs `init_function`, every other caller (including concurrent
ones) blocks until it has finished, and nobody runs it twice.

Contract for `107.c`:

- A `static int value;` and a `static int init_count;`.
- `static void init(void)` increments `init_count` and sets `value = 42`.
- `once_init_value()` calls `pthread_once(&control, init)` and then returns
  `value + 100 * (init_count - 1)`.

The arithmetic is how the test observes "exactly once" through a single
function: when `init` ran once, `init_count - 1` is `0` and every call
returns `42`; if it ran twice, calls return `142`; if it never ran, `value`
is `0` and `init_count - 1` is `-1`, so the result is `-100`. The test
calls `once_init_value` from 8 threads concurrently and from the main
thread afterwards, and expects `42` every time.

These statics are the exercise, so they are allowed. Do not use a mutex or
an atomic flag instead of `pthread_once` (both can be made to work, but
`pthread_once` is the idiom; `pthread_once` is also what C11's
`call_once` maps to). Reading `value` and `init_count` after
`pthread_once` returns is safe: `pthread_once` guarantees the
initialisation happens-before every return from it.

Examples: `once_init_value()` → `42`; a second call → `42`; 8 threads each
calling it 1000 times → every result `42`.
