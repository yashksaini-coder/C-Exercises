# 047 — 2D allocation in one block

Implement `int **matrix_alloc(size_t rows, size_t columns)` and
`void matrix_free(int **matrix)` in `047.c`.

Return a `rows × columns` matrix of `int`, zero-initialized, usable as
`matrix[r][c]`, that `matrix_free(matrix)` releases completely. Return
`NULL` when `rows == 0`, `columns == 0`, or allocation fails.
`matrix_free(NULL)` is a no-op.

The naive approach — one `malloc` for the row-pointer array plus one
`malloc` *per row* — needs `rows + 1` allocations and `rows + 1` frees,
scatters rows across the heap, and leaks on partial failure unless you
unwind carefully. Do better: make exactly **two** allocations (one array of
`rows` pointers, one contiguous block of `rows * columns` ints) and point
each `matrix[r]` at `data + r * columns`. `matrix_free` then frees
`matrix[0]` (the data block) and `matrix` (the pointer array).

Even nicer, and also accepted: a **single** allocation holding the pointer
array followed by the data — then `matrix_free` is just `free(matrix)`. If
you do that, mind alignment: `rows * sizeof(int *)` bytes is a multiple of
`_Alignof(int)` on every mainstream ABI, but be aware you are relying on it.
Either way, zero the data (`memset`, `calloc`, or a loop) and remember the
multiplication `rows * columns * sizeof(int)` can overflow for absurd sizes.

Allowed: `malloc`, `calloc`, `memset`, `free`.

Examples: `m = matrix_alloc(3, 4)` → `m[2][3] == 0` for every cell; after
`m[1][2] = 7`, `m[1][2] == 7` and `m[0][2] == 0`; rows are contiguous:
`m[1] == m[0] + 4`; `matrix_alloc(0, 5)` → `NULL`;
`matrix_alloc(5, 0)` → `NULL`.
