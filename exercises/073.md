# 073 — Floyd's cycle detection

Implement `bool list_has_cycle(const IntNode *head)` in `073.c`.

Return `true` if following `next` pointers from `head` never reaches
`NULL` — some node's `next` points back at an earlier node (or itself) —
and `false` otherwise. `NULL` → `false`.

Use Floyd's tortoise-and-hare: a `slow` pointer that advances one node per
step and a `fast` pointer that advances two. If there is no cycle, `fast`
(or `fast->next`) becomes `NULL` and you return `false`. If there is one,
`fast` eventually laps `slow` inside the loop and they point at the same
node — return `true`. O(n) time, O(1) space, no marking, no allocation, no
set of visited pointers. The check must be `fast && fast->next` *before*
dereferencing `fast->next->next`, or a list of odd length crashes.

Why it works: once both pointers are inside the cycle the gap between them
shrinks by one each step, so they must meet within one cycle length.

The tests build cycles by hand with stack-allocated nodes
(`last.next = &first;`) and break them before cleanup; nothing is
allocated.

Examples: `1 → 2 → 3 → NULL` → `false`; `1 → 2 → 3 → (back to 1)` →
`true`; a single node pointing to itself → `true`; `NULL` → `false`.

> Read: Beej's Guide to C, §5 Pointers — https://beej.us/guide/bgc/html/split/pointers.html
