# 093 — struct sockaddr and inet_ntop

Implement `int sockaddr_to_string(const struct sockaddr *address, char *destination, size_t capacity)`
in `093.c`.

Every socket call that hands you a peer address (`accept`, `recvfrom`,
`getaddrinfo`) gives you a generic `struct sockaddr *`. The first field,
`sa_family`, tells you which concrete struct it really is: `AF_INET` means
`struct sockaddr_in` (with `sin_addr` and `sin_port`), `AF_INET6` means
`struct sockaddr_in6` (with `sin6_addr` and `sin6_port`). Cast the pointer to
the right type and read the fields.

Format the address and port into `destination`, NUL-terminated:

- `AF_INET` → `"A.B.C.D:port"`, e.g. `"127.0.0.1:8080"`.
- `AF_INET6` → `"[v6]:port"`, e.g. `"[::1]:443"`, using the compressed form
  `inet_ntop` produces.

Return `0` on success. Return `-1` for any other family, for a `NULL`
pointer, or when the result plus its NUL does not fit in `capacity`
(`INET6_ADDRSTRLEN + 8` is always enough).

This exercise *allows* `inet_ntop` and `snprintf`: the point is navigating
the structs, not formatting bytes. Remember the port is stored in network
byte order; convert with `ntohs` before printing. Check `snprintf`'s return
value against `capacity` to detect truncation.

Examples: a `sockaddr_in` for `127.0.0.1` port `8080` → `"127.0.0.1:8080"`;
a `sockaddr_in6` for `::1` port `443` → `"[::1]:443"`; a `sockaddr` with
`sa_family = AF_UNIX` → `-1`; `127.0.0.1:8080` into a 10-byte buffer → `-1`.
