# 066 — Callbacks with context

Implement `int emitter_connect(Emitter *emitter, EventHandler handler, void *context)`
and `void emitter_emit(Emitter *emitter, int event)` in `066.c`.

The header defines:

```c
typedef void (*EventHandler)(void *context, int event);
typedef struct { EventHandler handlers[8]; void *contexts[8]; size_t count; } Emitter;
```

An `Emitter` is a list of up to 8 subscribers. Each subscriber is a function
pointer **plus** a `void *context` that is handed back to it on every call.
The context is what makes C callbacks usable: without it a handler can only
touch globals. With it, the same handler function can serve many objects
(this is `this` in C++, `self` in Python, a closure's captured environment
elsewhere). The emitter never looks inside `context`; it is an opaque
cookie that belongs to the subscriber.

Contract:

- The caller zero-initialises the emitter (`Emitter e = {0};`), so
  `count == 0` at the start.
- `emitter_connect` stores `handler` and `context` at index `count` and
  increments `count`; returns `0` on success and `-1` when 8 handlers are
  already registered (nothing is stored). A `NULL` handler → `-1`.
- `emitter_emit(e, event)` calls every registered handler in registration
  order as `handler(context, event)`. Zero handlers → nothing happens.

No allocation, no globals.

Examples: connect a handler whose context is an `int *` that it adds
`event` to; emit `5` then `7` → the int is `12`. Connect the same handler
twice with two different ints; emit `1` → both ints are `1`. Nine connects
→ the ninth returns `-1`, `count` stays `8`.
