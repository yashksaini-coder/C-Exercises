# 048 — Overflow-checked allocation

Implement `void *my_calloc(size_t count, size_t size)` in `048.c`.

Allocate `count * size` bytes, set every byte to zero, and return the
pointer; the caller frees it with `free()`. Return `NULL` when the
multiplication `count * size` would overflow `size_t`, or when the
underlying allocation fails. When `count` or `size` is `0`, return the
result of `malloc(0)` — either `NULL` or a unique pointer that can be
freed; the tests accept both.

The whole point is the overflow check. `size_t` arithmetic wraps silently,
so `my_calloc(SIZE_MAX / 2, 4)` computes a small number and a naive
`malloc(count * size)` would hand back a tiny block that the caller then
writes gigabytes into. Real `calloc` guards against this; `malloc(n * m)`
does not, which is why it has been the source of many CVEs. Check *before*
multiplying: `if (size != 0 && count > SIZE_MAX / size) return NULL;`.
(A division per call is cheap; the fast path in libc skips it when both
operands fit in 32 bits.)

Forbidden: `calloc` — you are reimplementing it. Allowed: `malloc`,
`memset`, `SIZE_MAX` from `<stdint.h>`.

Examples: `p = my_calloc(10, sizeof(int))` → 40 zero bytes;
`my_calloc(SIZE_MAX / 2, 4)` → `NULL`; `my_calloc(SIZE_MAX, 2)` → `NULL`;
`my_calloc(SIZE_MAX / 4 + 1, 4)` → `NULL` (off by one past the limit).
