# 040 — Flexible array members

Implement `OwnedString *owned_string_new(const char *s)` in `040.c`.

`OwnedString` is `typedef struct { size_t length; char data[]; } OwnedString;`.
The last member, `char data[]`, is a *flexible array member* (C99): it has
no size, contributes nothing to `sizeof(OwnedString)`, and may only appear
last. The idea is that the struct header and its variable-length payload
live in **one** allocation, so there is one `malloc`, one `free`, and the
bytes are adjacent in memory (better cache behavior, fewer pointer chases).

Allocate exactly `sizeof(OwnedString) + length + 1` bytes with a single
`malloc`, where `length = strlen(s)`. Copy the string including its NUL
terminator into `data`, set `length`, and return the pointer. The caller
releases it with a plain `free(result)` — there is no separate `data`
allocation to free.

Return `NULL` when `s` is `NULL` or when `malloc` fails. An empty string is
valid: `length` is `0` and `data[0]` is `'\0'`.

Allowed: `malloc`, `strlen`, `memcpy` (or `my_strlen`/`my_strcpy` from
Stage 3). Do not call `strdup`; do not allocate `data` separately (that
defeats the point, and `free(result)` would leak it).

Examples: `owned_string_new("hello")` → `length == 5`, `data == "hello"`;
`owned_string_new("")` → `length == 0`, `data == ""`;
`owned_string_new(NULL)` → `NULL`. The returned struct's `data` must be
located immediately after the header: `(char *)result + offsetof(OwnedString,
data) == result->data`.
