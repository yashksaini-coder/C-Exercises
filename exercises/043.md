# 043 — Growable vector with realloc

Implement `int vector_push(IntVector *vector, int value)` and
`void vector_free(IntVector *vector)` in `043.c`.

`IntVector` is `typedef struct { int *data; size_t length, capacity; } IntVector;`.
A zero-initialized vector (`IntVector v = {0};`) is valid and empty:
`data == NULL`, `length == 0`, `capacity == 0`.

`vector_push` appends `value` at index `length`, growing storage when
`length == capacity`. Growth policy: from capacity `0` go to `4`; after
that double (`4 → 8 → 16 → …`). Grow with `realloc(vector->data, new_capacity
* sizeof(int))`, which preserves the existing elements. Return `0` on
success and `-1` on allocation failure or when `vector` is `NULL`; on
failure the vector must be unchanged — so `realloc` into a *temporary*
pointer and only assign `vector->data` after checking for `NULL`. Assigning
`vector->data = realloc(vector->data, …)` directly is the classic bug: on
failure the old block leaks and the pointer becomes `NULL`.

`vector_free` releases `data` and resets all three fields to zero, so the
vector can be reused or freed again safely. `vector_free(NULL)` is a no-op.

Amortized analysis: doubling makes `n` pushes cost `O(n)` total even though
individual pushes occasionally copy everything. That is why every dynamic
array (C++ `std::vector`, Python lists, Go slices) grows geometrically.

Allowed: `realloc`, `free`, `malloc`. No fixed maximum size.

Examples: after three pushes of `1, 2, 3` into `{0}`: `length == 3`,
`capacity == 4`, `data == {1,2,3}`; after a fifth push `capacity == 8`;
after 100 pushes `length == 100`, `capacity == 128`;
`vector_free(&v)` → `data == NULL`, `length == 0`, `capacity == 0`.
