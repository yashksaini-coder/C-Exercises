# 084 — Variadic functions

Implement `long sum_ints(size_t count, ...)` in `084.c`.

Return the sum of the `count` `int` arguments that follow `count`. With
`count == 0` there are no further arguments and the result is `0`. Sum in
a `long` so that, for example, `INT_MAX + INT_MAX` does not overflow on
platforms where `long` is 64-bit (the test uses it).

The mechanics, from `<stdarg.h>`:

1. Declare a `va_list args;`
2. `va_start(args, count);` — `count` is the last *named* parameter.
3. `va_arg(args, int)` once per argument, in order. The type you name must
   match what the caller passed *after default argument promotions*:
   `char` and `short` arrive as `int`, `float` as `double`. Asking for the
   wrong type is undefined behaviour, not a conversion.
4. `va_end(args);` before returning — always, on every path.

A variadic function has no way to know how many arguments were passed or
their types; `count` carries that information, just as `printf`'s format
string does. Passing a `count` larger than the real argument list is
undefined behaviour on the caller's side; the function cannot detect it.

Examples: `sum_ints(3, 1, 2, 3)` → `6`; `sum_ints(0)` → `0`;
`sum_ints(1, -7)` → `-7`; `sum_ints(2, INT_MAX, INT_MAX)` →
`4294967294` (as a `long`).
