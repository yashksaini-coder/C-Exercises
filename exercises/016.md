# 016 — Pointer subtraction

Implement `ptrdiff_t pointer_distance(const int *first, const int *second)` in `016.c`.

Return how many `int` elements lie between `first` and `second`, as
`second - first`: positive when `second` is further along the array,
negative when it is earlier, `0` when both point at the same element.
Both pointers always point into the same array (or one past its end), which
is the only situation in which C defines pointer subtraction; the tests
never violate this, and neither may your playground.

The whole exercise is one expression. Subtracting two pointers of the same
type yields a `ptrdiff_t` measured in *elements*, not bytes — the compiler
divides by `sizeof(int)` for you. Do not cast to `char *` or to integers and
do not divide by `sizeof(int)` yourself; that gives a wrong answer by a
factor of four. No library calls.

Examples: with `int v[8]`: `pointer_distance(v, v + 5)` → `5`;
`pointer_distance(v + 5, v)` → `-5`; `pointer_distance(&v[3], &v[3])` → `0`;
`pointer_distance(v, v + 8)` → `8` (one past the end is allowed).
