# 114 — Re-entrant tokenizer (strtok_r)

Implement `char *next_token(char *s, const char *delimiters, char **state)`
in `114.c`.

Re-implement `strtok_r`. The first call passes the string in `s`; each
later call passes `NULL` for `s` and the same `state` pointer, and the
function continues where it left off. Every call returns the next token,
or `NULL` when none remain.

Semantics, exactly those of `strtok_r`:

- A token is a maximal run of characters not in `delimiters`. Consecutive
  delimiters produce *no* empty tokens: `"a,,b"` with `","` yields `"a"`,
  `"b"`. Leading and trailing delimiters are skipped.
- The string is modified in place: the delimiter that ends a token is
  overwritten with `'\0'`, so the returned pointer is a proper C string
  pointing *into* `s`. Nothing is allocated.
- `*state` holds where to resume. All of the tokenizer's state lives
  there, so two tokenizations can be interleaved and the function is safe
  to call from several threads at once. **No `static` or global
  variables**, which is exactly what makes `strtok` unsafe.
- `delimiters` may change between calls: `"a=1;b=2"` with `"="` then
  `";"` yields `"a"`, `"1"`.
- Passing `s == NULL` with `*state == NULL` (nothing started, or finished)
  returns `NULL`.

Use `strspn` to skip leading delimiters and `strcspn` to find the end of
a token, or write the character tests yourself; `strchr` on `delimiters`
is fine. Forbidden: `strtok`, `strtok_r`, `strsep`.

Examples: `"one two  three"` with `" "` → `"one"`, `"two"`, `"three"`,
`NULL`; `",,a,,b,,"` with `","` → `"a"`, `"b"`, `NULL`; `""` → `NULL`;
`"a=1;b=2"` with `"="`, then `";"`, then `"="`, then `";"` → `"a"`,
`"1"`, `"b"`, `"2"`; two tokenizers interleaved on two strings do not
disturb each other.
