# 068 — _Generic selections

Implement `const char *describe_int(int value)`, `const char *describe_double(double value)`
and `const char *describe_string(const char *value)` in `068.c`.

The header defines a type-dispatching macro:

```c
#define TYPE_NAME(x) _Generic((x), int: "int", double: "double", char: "char", \
                              char *: "char *", const char *: "const char *", default: "unknown")
```

`_Generic` (C11) is a compile-time switch on the *type* of its controlling
expression. It is how `<tgmath.h>` makes `sqrt(x)` call `sqrtf`, `sqrt` or
`sqrtl` depending on `x`. It is not run-time polymorphism: the selection is
fixed when the file is compiled, and the unselected branches are never
evaluated (they only need to type-check).

Each `describe_*` function returns `TYPE_NAME(value)` for its parameter.
That is all — the exercise is about reading the macro and predicting its
output:

- `describe_int(7)` → `"int"`, `describe_double(2.5)` → `"double"`.
- `describe_string("hi")` → `"const char *"`, because the parameter's type
  is exactly `const char *` and `_Generic` matches types exactly (after
  lvalue conversion, so array-to-pointer and qualifier dropping on the
  *outer* type happen, but `const char *` and `char *` are different
  pointer types and do not match each other).

Do not return string literals directly; use the macro so the compiler does
the dispatch. Note that `TYPE_NAME('a')` would be `"int"` in C, not
`"char"`: a character constant has type `int`. The `char` branch exists to
show that `_Generic` sees through nothing — only a `char`-typed expression
selects it.

Examples: `describe_int(0)` → `"int"`; `describe_double(-1e9)` →
`"double"`; `describe_string(NULL)` → `"const char *"` (the value is never
read).
