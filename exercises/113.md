# 113 — Quickselect

Implement `int kth_largest(int *values, size_t count, size_t k)` in `113.c`.

Return the `k`-th largest value, with `k` 1-based: `k = 1` is the maximum,
`k = count` is the minimum. Duplicates count separately, so in
`{3, 3, 1}` the 2nd largest is `3`, not `1`. The caller guarantees
`1 <= k <= count` and `count >= 1`; for anything else return `INT_MIN`
and do nothing (defined so the test can check it, not so callers rely on
it).

The function takes a non-`const` array on purpose: you may reorder
`values`. The expected approach is quickselect, O(n) average: pick a
pivot, partition so that larger values come first, then recurse (or
loop) into the side that contains index `k - 1`. Sorting with `qsort` and
indexing is accepted as a fallback, but write the partition at least
once; it is what the interviewer is after. Both approaches must handle
all-equal input (a naive partition degrades to O(n²) or loops forever on
it) and `INT_MIN`/`INT_MAX` as values.

No `malloc`, no global state. Use the middle element (or the median of
first/middle/last) as the pivot; the first element makes sorted input
quadratic.

Examples: `kth_largest({3, 2, 1, 5, 6, 4}, 6, 2)` → `5`;
`kth_largest({3, 2, 3, 1, 2, 4, 5, 5, 6}, 9, 4)` → `4`;
`kth_largest({3, 3, 1}, 3, 2)` → `3`; `kth_largest({7}, 1, 1)` → `7`;
`kth_largest({5, 5, 5, 5}, 4, 3)` → `5`; `k = 0` or `k > count` →
`INT_MIN`.

> [!TIP]
> Read: Beej's Guide to C, §6 Arrays and §20.7 `qsort()` (for the fallback)
> — https://beej.us/guide/bgc/html/split/arrays.html
> LeetCode #215; "can you do better than sorting?" leads to quickselect
> or a heap of size k.
