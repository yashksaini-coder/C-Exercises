# 099 — accept and echo

Implement `int echo_serve_one(int listen_fd)` in `099.c`.

`listen_fd` is a listening TCP socket (as returned by 097). Accept exactly
one client, then echo: every byte the client sends is sent straight back
to it, until the client closes its side of the connection (`recv` returns
`0`). Then close the client socket and return `0`. Do *not* close
`listen_fd`; the caller owns it.

Return `-1` if `accept` fails (retry on `EINTR` first), or if a `send` or
`recv` fails mid-conversation (close the client socket before returning).

Details that matter:

- `accept(listen_fd, NULL, NULL)` is fine; you do not need the peer address.
- Read into a local buffer of a few KiB. Whatever `recv` returns, write
  back *that many* bytes, looping over partial sends (the loop from 094;
  copy it as a `static` helper, since 094 is not linked here).
- A client that writes with `shutdown(fd, SHUT_WR)` tells you it has
  finished sending but can still read your replies. Your `recv` sees `0`
  and you return; the client then reads the last echoes.

No threads, no `fork`, no global state; one client, then return. The
tests run your server in a thread and talk to it over loopback.

Examples: client sends `"hello"` → reads back `"hello"`; client sends
`"one"`, `"two"`, `"three"` in turn and reads each echo in order; client
sends 100000 bytes, shuts down writing, and reads exactly 100000 identical
bytes back; `echo_serve_one(-1)` → `-1`.
