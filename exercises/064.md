# 064 — Generic sort

Implement `void my_qsort(void *base, size_t count, size_t size, Comparator compare)`
in `064.c`.

Sort the `count` elements of `size` bytes each at `base` in ascending order
as defined by `compare` (negative means `a` before `b`). The signature is
`qsort`'s, and so is the contract: it works for any element type. **Do not
call `qsort`.** Any correct algorithm is accepted — insertion sort is fine
for this exercise, a quicksort or merge sort is better, but stability is not
required.

The part that matters is moving elements you cannot name. Address element
`i` as `(unsigned char *)base + i * size`. To swap two elements, swap them
byte by byte in a loop over `size` (or `memcpy` through a small temporary
buffer only when `size` fits — the byte loop has no such limit). Do not
declare a variable-length array of `size` bytes on the stack: a large
element would overflow it, and VLAs are optional in C11.

`count == 0` and `count == 1` must be no-ops. The tests sort `int`,
`double` and `Student` (with a comparator ordering like 035's: score
descending, then name ascending), so your swap must work for a 36-byte
struct too.

Examples: `{5, 1, 4, 2, 3}` → `{1, 2, 3, 4, 5}`; `{2.5, -1.0, 0.0}` →
`{-1.0, 0.0, 2.5}`; already sorted or single-element input is unchanged.
