# 077 — Tree recursion

Implement `size_t bst_height(const TreeNode *root)` and
`size_t bst_to_sorted_array(const TreeNode *root, int *out, size_t capacity)`
in `077.c`.

Both are recursive walks over the `TreeNode` tree from 076. The tests
build trees by hand from stack nodes, so 076 is not a dependency.

- `bst_height(root)` is the number of nodes on the longest root-to-leaf
  path: `NULL` → `0`, a single node → `1`, otherwise
  `1 + max(height(left), height(right))`. This is the natural shape of
  every tree recursion: handle `NULL`, recurse on children, combine.
- `bst_to_sorted_array(root, out, capacity)` performs an **in-order**
  traversal (left subtree, node, right subtree), which visits a BST's
  values in ascending order. Write each value into `out` while fewer than
  `capacity` have been written; never write past `capacity`. Return the
  number of values written (so `min(node count, capacity)`).
  `capacity == 0` → `0`, `out` untouched. The traversal must still be
  correct when it stops early, so pass the running count down (a pointer
  to a `size_t`, or a small helper struct) rather than using a global.

No allocation in either function.

Examples: tree `5(3(1, 4), 8)` → height `3`, sorted array
`{1, 3, 4, 5, 8}`; the same tree with capacity `3` → writes `{1, 3, 4}`
and returns `3`; a right-leaning chain `1 → 2 → 3` → height `3`; `NULL`
→ height `0`, array returns `0`.

> Read: Beej's Guide to C, §4 Functions (recursion) —
> https://beej.us/guide/bgc/html/split/functions.html
> Height and in-order traversal are the two tree warm-ups interviewers use
> before asking "now check whether it is a valid BST".
