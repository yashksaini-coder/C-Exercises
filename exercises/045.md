# 045 — Read a line of any length

Implement `char *read_line(FILE *stream)` in `045.c`.

Read one line from `stream` and return it as a newly allocated,
NUL-terminated string **without** the trailing `'\n'`. The caller frees it.
Return `NULL` when the stream is already at end-of-file (or on a read error)
and nothing was read. A final line that ends at EOF without a newline is
still returned. An empty line (`"\n"`) returns `""`, not `NULL` — the
difference between "read an empty line" and "nothing left" matters.

Lines can be arbitrarily long, so no fixed buffer. Read characters with
`fgetc` (or `getc`) one at a time into a buffer that you grow with `realloc`
(start around 16–64 bytes, double when full), stop at `'\n'` or `EOF`, and
NUL-terminate. Keep `+ 1` room for the terminator when you check capacity.
Compare `fgetc`'s result as an `int` against `EOF` before storing it as a
`char`: storing first then comparing breaks on byte `0xFF`. If `malloc`
or `realloc` fails, free what you have and return `NULL`.

Forbidden: `getline`, `getdelim`, `fgets` with a fixed buffer that would
truncate (`fgets` in a growing loop is allowed but fiddlier; `fgetc` is
simpler). `read_line(NULL)` returns `NULL`.

Examples (reading from a `tmpfile()` containing `"alpha\n\nlast"`):
first call → `"alpha"`; second → `""`; third → `"last"`; fourth → `NULL`.
A 5000-character line is returned intact with `strlen == 5000`.
