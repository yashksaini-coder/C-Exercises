# 095 — Reading exactly n bytes

Implement `int recv_exact(int fd, void *buffer, size_t length)` in `095.c`.

TCP is a byte stream with no message boundaries. A peer that sends 1000
bytes in one call may be read as 1000 bytes, or 536 then 464, or any other
split, and `recv` returns whatever has arrived so far. When a protocol says
"the next 8 bytes are a header", you must loop until you really have 8.

Contract: fill all `length` bytes of `buffer` from `fd` and return `0`.
Return values:

- `0` — all `length` bytes were received.
- `1` — the peer closed the connection (`recv` returned `0`) before `length`
  bytes arrived. This includes EOF after some bytes were already copied into
  `buffer`; the caller must treat the partial contents as garbage.
- `-1` — `recv` failed. Retry on `EINTR` rather than failing.

`length == 0` returns `0` without calling `recv`. Use `recv(fd, p, remaining, 0)`
or `read`; `MSG_WAITALL` is forbidden (it is the exercise), and so is
`readv`. No global state.

Examples: peer writes `"abcdef"` then `recv_exact(fd, buf, 4)` → `0`, `buf` is
`"abcd"`, and the `"ef"` is still waiting; peer writes `"ab"` and closes,
`recv_exact(fd, buf, 4)` → `1`; peer writes 65536 bytes in several pieces,
`recv_exact(fd, buf, 65536)` → `0` with every byte in place;
`recv_exact(fd, buf, 0)` → `0`; `recv_exact(-1, buf, 1)` → `-1`.
