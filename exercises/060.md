# 060 — RFC 1071 checksum

Implement `uint16_t internet_checksum(const unsigned char *data, size_t length)`
in `060.c`.

Compute the Internet checksum used by IPv4, ICMP, UDP and TCP headers
(RFC 1071). The algorithm:

1. Treat `data` as a sequence of 16-bit big-endian words. Read each word
   byte by byte (`(data[i] << 8) | data[i+1]`) — no casting to `uint16_t *`,
   the buffer may be unaligned.
2. If `length` is odd, the last byte is padded with a zero on the right:
   it contributes `data[length-1] << 8`.
3. Add all words into a 32-bit (or wider) accumulator.
4. Fold the carries: while `sum >> 16` is non-zero, `sum = (sum & 0xFFFF)
   + (sum >> 16)`. This is one's-complement addition; one `while` loop is
   needed because the fold itself can carry once more.
5. Return `~sum` truncated to 16 bits. The result is in *host* order as a
   number — to put it in a packet, write it with `write_u32_be`-style
   byte stores (high byte first).

The property that makes it useful: if you insert the checksum into the
data (in its 16-bit field at an *even* offset, big-endian) and run the
algorithm over the whole buffer again, the result is `0`. That is how receivers verify a
header. Note that the empty buffer sums to `0`, so its checksum is
`0xFFFF`.

Forbidden: `htons`/`ntohs`, any alignment-unsafe pointer cast.

Examples: the 20-byte IPv4 header
`45 00 00 3C 1C 46 40 00 40 06 00 00 AC 10 0A 63 AC 10 0A 0C` (checksum
field zeroed) → `0xB1E6`; the same header with `B1 E6` written at offset
10 → `0x0000`; `{0x01,0x02,0x03}` (odd length) → `0xFBFD`;
empty buffer → `0xFFFF`; `{0xFF,0xFF}` → `0x0000`;
`{0xFF,0xFF,0xFF,0xFF}` → `0x0000` (the fold must wrap twice).
