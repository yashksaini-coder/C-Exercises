# 086 — Macro pitfalls

Implement `size_t safe_min_calls(void)` in `086.c`.

`include/exercises.h` defines the textbook macro:

```c
#define MIN(a, b) ((a) < (b) ? (a) : (b))
```

The parentheses protect against precedence surprises, but a macro is text
substitution, not a function: `MIN(tick(), 100)` expands to
`((tick()) < (100) ? (tick()) : (100))`, which **evaluates `tick()`
twice** whenever the first call returns something below 100. The famous
form of this bug is `MIN(i++, j)`, which increments `i` twice.

This exercise makes you observe it. In `086.c`:

1. Keep a `static size_t calls;` counter and a `static int tick(void)`
   that increments `calls` and returns a small number (`1` is fine; it
   must be below `100`).
2. `safe_min_calls` sets `calls = 0`, evaluates `MIN(tick(), 100)` exactly
   once (use the result, e.g. assign it to a `volatile int`, so the
   compiler cannot drop the expression), and returns `calls`.

The expected return value is `2`. That is the whole point: a reader who
assumes `MIN` is a function predicts `1`. Do not "fix" the macro or
special-case the count — the function reports what actually happened.

Then write the fix next to it: `static inline int min_int(int a, int b)`
which evaluates each argument exactly once because function arguments
are evaluated before the call. Use it in your playground `main` to show
`min_int(tick(), 100)` costs one call. (In C11 you could also write a
type-generic version with `_Generic`, as in 068.)

Other macro traps worth knowing, in the same spirit: a multi-statement
macro without `do { ... } while (0)` breaks `if` without braces; a macro
parameter used unparenthesised breaks on `MIN(a | b, c)`; and `#define
SQUARE(x) x * x` gives `SQUARE(1 + 1) == 3`.

Examples: `safe_min_calls()` → `2`; calling it twice → `2` both times
(the counter is reset each call).
