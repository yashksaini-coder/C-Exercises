# 067 — Inheritance by embedding

Implement `Animal *animal_new_dog(const char *name)`, `Animal *animal_new_cat(const char *name)`,
`const char *animal_speak(const Animal *animal)` and `void animal_free(Animal *animal)`
in `067.c`.

The header defines the base class:

```c
struct Animal { const char *(*speak)(const Animal *self); const char *name; };
```

Unlike 062 there is no separate vtable: the function pointer lives directly
in the object. A function pointer stored in a struct *is* a virtual method —
calling `animal->speak(animal)` picks the behaviour at run time from
whatever the constructor stored there. Both styles exist in real code: a
per-object pointer costs 8 bytes per method per object but lets you override
per instance; a shared vtable costs one pointer per object.

Contract:

- Each constructor `malloc`s an object (either a bare `Animal`, or a
  `struct Dog { Animal base; ... }` with extra fields if you want to extend
  it — `base` first, as in 062), copies `name` into memory it owns (you may
  reuse the idea of 041 `my_strdup`, or call `strdup`/`malloc`+`strcpy`),
  and sets `speak`. Returns `NULL` if any allocation fails, leaking nothing.
- Dogs say `"Woof"`, cats say `"Meow"` (string literals).
- `animal_speak(a)` returns `a->speak(a)`; it must not inspect the name or
  compare anything — the dispatch is the point.
- `animal->name` must compare equal to the string given to the constructor
  but must **not** point at the caller's buffer (the test overwrites the
  caller's buffer after constructing).
- `animal_free(a)` frees the name and the object; `animal_free(NULL)` is a
  no-op.

Examples: `animal_speak(animal_new_dog("Rex"))` → `"Woof"`;
`animal_speak(animal_new_cat("Tom"))` → `"Meow"`;
`animal_new_cat("Tom")->name` → `"Tom"`.
