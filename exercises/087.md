# 087 — Error codes and errno style

Implement `Error safe_divide(int a, int b, int *out)` and
`const char *error_string(Error error)` in `087.c`.

```c
typedef enum { ERR_OK, ERR_DIVIDE_BY_ZERO, ERR_OVERFLOW, ERR_INVALID } Error;
```

C has no exceptions. The standard library reports failure two ways: a
sentinel return value (`NULL`, `-1`, `EOF`) with the detail in the global
`errno`, or — the cleaner style used by most modern C APIs — a returned
status code with the real result delivered through an out-parameter. This
exercise is the second style.

- `safe_divide(a, b, out)`:
  - `b == 0` → return `ERR_DIVIDE_BY_ZERO`, `*out` untouched.
  - `a == INT_MIN && b == -1` → return `ERR_OVERFLOW`, `*out` untouched.
    The true quotient `2147483648` does not fit in an `int`; evaluating
    `INT_MIN / -1` is undefined behaviour and on x86 raises `SIGFPE`.
    Check *before* dividing.
  - otherwise `*out = a / b` and return `ERR_OK`.
  - `out == NULL` → `ERR_INVALID` (checked first, before any division).
- `error_string(e)` returns a string literal: `ERR_OK` → `"ok"`,
  `ERR_DIVIDE_BY_ZERO` → `"divide by zero"`, `ERR_OVERFLOW` →
  `"overflow"`, `ERR_INVALID` → `"invalid"`; any other value (the enum is
  just an `int`, so callers can pass `42`) → `"invalid"` too. Use a
  `switch` with a `default`; this is what `strerror` does for `errno`.

The useful convention — zero means success — lets callers write
`if (safe_divide(a, b, &q)) { handle(error); }`. Keep it: `ERR_OK` is `0`
by position in the enum.

Examples: `safe_divide(7, 2, &q)` → `ERR_OK`, `q == 3`;
`safe_divide(1, 0, &q)` → `ERR_DIVIDE_BY_ZERO`; `safe_divide(INT_MIN, -1,
&q)` → `ERR_OVERFLOW`; `safe_divide(INT_MIN, 1, &q)` → `ERR_OK`, `q ==
INT_MIN`; `error_string(ERR_OVERFLOW)` → `"overflow"`.
