# 056 — Encode big-endian bytes

Implement `void write_u32_be(unsigned char *bytes, uint32_t value)` in
`056.c`.

Store `value` into the four bytes at `bytes` in big-endian order: the most
significant byte first. `bytes[0] = value >> 24`, `bytes[1] = value >> 16`,
`bytes[2] = value >> 8`, `bytes[3] = value`, each truncated to 8 bits by
the assignment to `unsigned char` (mask with `& 0xFF` if you prefer to be
explicit). This is the inverse of `read_u32_be` (055).

As in 055, do **not** cast `bytes` to `uint32_t *` and store through it:
the destination may be unaligned, and the host's byte order is not the
wire's. Writing one byte at a time is correct on every machine and
compiles to one instruction on the fast ones. Forbidden: `htonl`, `memcpy`
of a swapped `uint32_t`.

This pair of functions is how every binary protocol — TCP/IP headers, TLS
records, PNG chunks, Git packfiles — serializes integers, and how
`pack`/`unpack` (058/059) will do it too.

Examples: `write_u32_be(b, 1)` → `{0x00,0x00,0x00,0x01}`;
`write_u32_be(b, 0x12345678)` → `{0x12,0x34,0x56,0x78}`;
`write_u32_be(b, 0xFFFFFFFF)` → `{0xFF,0xFF,0xFF,0xFF}`; writing into the
middle of a larger buffer touches exactly 4 bytes.
