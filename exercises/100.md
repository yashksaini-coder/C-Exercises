# 100 — poll()

Implement `int wait_readable(const int *fds, size_t count, int timeout_ms, bool *ready)`
in `100.c`.

A server with many connections cannot block in `recv` on one of them while
the others wait. `poll()` takes an array of descriptors and sleeps until at
least one has something to report, or a timeout passes.

Contract: build a `struct pollfd` array from `fds` (one entry per
descriptor, `events = POLLIN`), call `poll(array, count, timeout_ms)`, and
set `ready[i] = true` when descriptor `i` is readable (its `revents` has
`POLLIN`, or `POLLHUP`/`POLLERR`, since a `recv` on those returns
immediately too) and `false` otherwise. Return the number of `true`
entries; `0` means the timeout expired with nothing ready; `-1` means
`poll` failed. Retry on `EINTR` instead of failing. `count == 0` returns
`0` immediately (after clearing nothing). A `timeout_ms` of `-1` waits
forever; `0` just checks.

Allocate the `pollfd` array with `malloc` (and free it) or, if you prefer,
cap `count` at a fixed local array and return `-1` above it; say which in a
comment. Do not use `select` (its `FD_SETSIZE` limit is the reason `poll`
exists) and do not use `epoll` (Linux-only).

Examples: two idle `socketpair` ends, `timeout_ms = 50` → `0`, both `ready`
`false`, and the call returns after roughly 50 ms; write a byte to one end,
then `wait_readable` on the other → `1` with that entry `true`; both ends
have data → `2`; `count = 0` → `0`; a closed descriptor (`-1` in `fds`) is
ignored by `poll` and stays `false`.
