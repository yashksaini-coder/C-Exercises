# 079 — LRU cache

Implement `void lru_init(LruCache *cache, size_t capacity)`,
`bool lru_get(LruCache *cache, int key, int *out)`,
`int lru_put(LruCache *cache, int key, int value)` and
`void lru_free(LruCache *cache)` in `079.c`.

Types from the header:

```c
typedef struct LruNode { int key, value; struct LruNode *prev, *next; } LruNode;
typedef struct { size_t capacity, count; LruNode *head, *tail; } LruCache;
```

A least-recently-used cache holds at most `capacity` key/value pairs. The
nodes form a doubly-linked list ordered by recency: `head` is the most
recently used entry, `tail` the least. Any access (get or put) moves the
touched node to the front; when a put makes `count` exceed `capacity`, the
`tail` node is unlinked and freed.

Contract:

- `lru_init(c, capacity)` sets `capacity` and zeroes `count`, `head`,
  `tail`. `capacity` is at least `1`.
- `lru_get(c, key, out)`: if `key` is present, move its node to the front,
  set `*out` and return `true`; otherwise `false`, `*out` untouched, and
  the order is unchanged.
- `lru_put(c, key, value)`: if `key` is present, update its value and move
  it to the front. Otherwise `malloc` a node, insert it at the front,
  increment `count`; if `count > capacity`, remove and `free` the tail and
  decrement `count`. Returns `0`, or `-1` if `malloc` fails (cache
  unchanged).
- `lru_free(c)` frees every node and resets `count`, `head`, `tail`.

Find keys by **walking the list** (O(n)); the point of this exercise is
the recency bookkeeping, not the lookup. A production cache pairs this
list with a hash map (075) so lookup is O(1) too — say so if asked. The
doubly-linked unlink must fix four cases: the node is the head, the tail,
both (single node) or in the middle. Write one `unlink(cache, node)` and
one `push_front(cache, node)` helper and build everything from those; the
"move to front" is `unlink` then `push_front`.

Examples (capacity 2): put `1→1`, put `2→2`, get `1` → `1`; put `3→3`
evicts `2` (least recent) so get `2` → `false`, get `3` → `3`; put `1→10`
updates in place, `count` stays `2`; `lru_get` on a missing key must not
reorder anything.
