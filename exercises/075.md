# 075 — Hash map with chaining

Implement `uint64_t hash_djb2(const char *s)`,
`int hashmap_put(HashMap *map, const char *key, int value)`,
`bool hashmap_get(const HashMap *map, const char *key, int *out)` and
`void hashmap_free(HashMap *map)` in `075.c`.

Types from the header:

```c
typedef struct HashEntry { char *key; int value; struct HashEntry *next; } HashEntry;
typedef struct { HashEntry *buckets[64]; size_t count; } HashMap;
```

`hash_djb2` is Dan Bernstein's string hash: start with `5381`, and for
each byte `c` set `h = h * 33 + c` (use `uint64_t`; wraparound is fine
and intended). Treat the bytes as `unsigned char`. `""` → `5381`,
`"a"` → `177670`, `"ab"` → `5863208`.

The map has 64 buckets; a key goes in bucket `hash_djb2(key) % 64`. Each
bucket is a singly linked chain of entries (separate chaining); collisions
simply share a chain. The caller zero-initialises the map
(`HashMap m = {0};`), so all buckets are `NULL` and `count == 0`.

Contract:

- `hashmap_put(m, key, value)`: if `key` already exists, overwrite its
  value and return `0` without allocating. Otherwise allocate an entry,
  **copy the key** (`strdup`, or `malloc` + `strcpy`; the caller may reuse
  its buffer), push it onto the front of the chain, increment `count`, and
  return `0`. Return `-1` on allocation failure, leaking nothing.
- `hashmap_get(m, key, out)`: `true` and `*out = value` if present, else
  `false` with `*out` untouched.
- `hashmap_free(m)`: free every entry's key and the entry itself, then
  leave the map in its zero state (all buckets `NULL`, `count == 0`).
  Save `next` before `free`.

Compare keys with `strcmp`, never by hash: equal hashes do not mean equal
keys. `count` is the number of distinct keys stored.

Examples: put `"one"→1`, `"two"→2`; get `"one"` → `true, 1`; get `"three"`
→ `false`; put `"one"→100` → get returns `100` and `count` stays `2`;
inserting 200 keys (`"k0"`…`"k199"`) forces collisions and every key must
still be retrievable.
