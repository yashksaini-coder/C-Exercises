# 094 — Handling partial sends

Implement `int send_all(int fd, const void *buffer, size_t length)` in `094.c`.

`send()` (and `write()`) may send *fewer* bytes than you asked for: the
kernel's socket buffer was partly full, so it took what fit and returned
that count. Code that calls `send` once and assumes everything went out
works on small messages and silently drops data on large ones. The fix is a
loop: send, advance the pointer by the number of bytes actually sent, repeat
until nothing remains.

Contract: send all `length` bytes of `buffer` on `fd` and return `0`.
Return `-1` if `send` fails. One failure is not a failure: `EINTR` means a
signal interrupted the call before anything was sent; retry it. Treat a
return of `0` from `send` as an error too (it cannot make progress).
`length == 0` returns `0` without calling `send`.

Use `send(fd, p, remaining, 0)` or `write`; do not use `sendfile`,
`writev` or `MSG_WAITALL`. No global state. Each exercise is compiled on its
own, so later exercises that want this loop must either copy it or move it
into `lib.c` (declared in `lib.h`); see 096.

The test sends 1 MiB through a `socketpair` whose send buffer is tiny while
a second thread drains the other end, so a single `send` call cannot
possibly succeed in one go.

Examples: `send_all(fd, "hello", 5)` → `0`, peer reads `"hello"`;
`send_all(fd, big, 1048576)` → `0`, peer reads exactly 1048576 bytes
byte-for-byte equal; `send_all(fd, buf, 0)` → `0`; `send_all(-1, buf, 5)`
→ `-1`.

> [!TIP]
> Read: Beej's Guide to Network Programming, §7.4 Handling Partial `send()`s
> — https://beej.us/guide/bgnet/html/split-wide/slightly-advanced-techniques.html
> This is the single most common bug in beginner socket code and a favourite
> interview follow-up: "what if `send` returns less than you asked?"
