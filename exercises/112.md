# 112 — Merge sorted arrays

Implement `void merge_sorted_arrays(const int *a, size_t a_count, const int *b, size_t b_count, int *out)`
in `112.c`.

`a` and `b` are each sorted ascending. Write all `a_count + b_count`
values into `out` in ascending order. The caller guarantees `out` has
room. The merge must be *stable*: when an element of `a` equals an
element of `b`, the one from `a` comes first. (You cannot tell equal
ints apart here, but the same loop is used on records, where it matters;
the test for it is the `<=` in your comparison.)

Walk both inputs with two indices, copying the smaller head each time;
when one input runs out, copy the rest of the other. O(n) time, no
`malloc`, no `qsort` (merging is the point; sorting the concatenation is
O(n log n) and the wrong answer in an interview). `memcpy` is fine for
the tail. Either array may be empty, and `a`/`b` may be `NULL` when their
count is `0`.

Examples: `{1, 3, 5}` + `{2, 4, 6}` → `{1, 2, 3, 4, 5, 6}`; `{1, 2, 3}` +
`{}` → `{1, 2, 3}`; `{}` + `{}` → nothing written; `{1, 1}` + `{1}` →
`{1, 1, 1}`; `{-5, 10}` + `{-10, 0, 20}` → `{-10, -5, 0, 10, 20}`;
`{1, 2}` + `{3, 4}` → `{1, 2, 3, 4}` (one side exhausted early).

> Read: Beej's Guide to C, §6 Arrays —
> https://beej.us/guide/bgc/html/split/arrays.html
> This is the inner step of merge sort and of every "merge k sorted
> streams" problem; the tail-copy is the part people forget.
