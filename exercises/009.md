# 009 — Integer to floating point

Implement `double average(const int *values, size_t count)` in `009.c`.

Return the arithmetic mean of the first `count` elements of `values` as a
`double`. When `count` is `0` return `0.0` (there is nothing to divide, and
the caller may pass `NULL` in that case; do not read from `values`).

Two things go wrong in first attempts. First, integer division: `sum / count`
with an integer `sum` truncates, so the average of `1, 2` becomes `1` instead
of `1.5`. Convert before dividing: `(double)sum / (double)count`. Second,
overflow: a few `INT_MAX` values summed into an `int` overflow (undefined
behaviour; `SANITIZE=1` reports it). Accumulate in `long long` or directly in
a `double`. The tests include three `INT_MAX` values, whose average must come
back as exactly `2147483647.0`, and a mix of `INT_MIN` and `INT_MAX`.

No library calls beyond what is already included.

Examples: `average({1, 2, 3, 4}, 4)` → `2.5`; `average({1, 2}, 2)` → `1.5`;
`average({-3}, 1)` → `-3.0`; `average(NULL, 0)` → `0.0`;
`average({INT_MAX, INT_MAX, INT_MAX}, 3)` → `2147483647.0`.

> [!TIP]
> Read: Beej's Guide to C, §15 Types III: Conversions (§15.2 Numeric
> conversions) — https://beej.us/guide/bgc/html/split/types-iii-conversions.html

Run `make run N=9`; check with `make test N=9`.
