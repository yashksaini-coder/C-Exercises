# 102 — Parsing an HTTP request line

Implement `bool parse_request_line(const char *line, RequestLine *out)` in `102.c`.

The first line of an HTTP/1.x request is three tokens separated by single
spaces: `METHOD SP PATH SP VERSION`, e.g. `GET /index.html HTTP/1.1`. Split
`line` into `out->method`, `out->path` and `out->version` (each
NUL-terminated) and return `true`. The struct is fixed-size:

```c
typedef struct { char method[8]; char path[256]; char version[16]; } RequestLine;
```

so each token must fit in its array *with* the NUL: a method of up to 7
characters, a path of up to 255, a version of up to 15. Return `false` when
a token is too long; do not truncate silently (truncating a path turns
`/admin/../secret` into `/admin`, which is a security bug, not a convenience).

Also `false`: fewer than three tokens (`"GET /"`); an empty token (two
spaces in a row, a leading space); anything after the version (`"GET / HTTP/1.1 extra"`,
a trailing space); or a `\r` or `\n` anywhere (the caller strips the line
ending; a CR in the middle is an attack). Do not validate the method's
spelling or the version's format beyond length: `"BREW / HTCPCP/1.0"` is
accepted. On `false`, `out` is unspecified.

Walk the string with a pointer and copy each token with a bounded loop or
`memcpy` after measuring it. No `sscanf` (its `%s` has no bound unless you
hard-code widths, and even then it skips whitespace you must reject), no
`strtok` (it merges consecutive separators).

Examples: `"GET /index.html HTTP/1.1"` → `true`, `{"GET", "/index.html",
"HTTP/1.1"}`; `"POST / HTTP/1.0"` → `{"POST", "/", "HTTP/1.0"}`;
`"GET /"` → `false`; `"GET  / HTTP/1.1"` → `false`; `"OPTIONSX / HTTP/1.1"`
(8-character method) → `false`; a 255-character path → `true`, a
256-character path → `false`.
