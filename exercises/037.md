# 037 — offsetof and container_of

Implement `Record *record_from_weight(double *weight_pointer)` in `037.c`.

`Record` is `typedef struct { int id; char tag[8]; double weight; } Record;`.
You are given a pointer to the `weight` member of some `Record` and must
return a pointer to the whole `Record` that contains it. Return `NULL` when
`weight_pointer` is `NULL`.

The tool is `offsetof(Type, member)` from `<stddef.h>`: it evaluates, at
compile time, to the byte distance from the start of `Type` to `member`.
Subtract that many bytes from the member's address — through a `char *`,
because pointer arithmetic on `char *` moves one byte at a time — and cast
the result back to `Record *`. The header already defines exactly that:

```c
#define CONTAINER_OF(pointer, Type, member) \
    ((Type *)((char *)(pointer) - offsetof(Type, member)))
```

Use it, or write the arithmetic by hand. Do not guess the offset: `int id`
is 4 bytes and `char tag[8]` is 8, but `double` needs 8-byte alignment, so
the compiler may insert padding and `offsetof(Record, weight)` is whatever
the ABI says (16 on x86-64 here, but your code must not hard-code it).
`sizeof(Record)` likewise includes trailing padding. This is why you never
compute struct layouts by adding member sizes.

This is the `container_of` macro at the heart of the Linux kernel: a
`struct list_head` is embedded inside every object, generic list code only
sees the `list_head`, and `container_of` recovers the owning object. Any
intrusive data structure (lists, trees, timers) works the same way.

Allowed: `offsetof`, `CONTAINER_OF`. No library calls.

Examples: for `Record r = {7, "abc", 2.5}`, `record_from_weight(&r.weight)`
→ `&r`, and `record_from_weight(&r.weight)->id` → `7`;
`record_from_weight(NULL)` → `NULL`. For an array `Record rs[3]`,
`record_from_weight(&rs[2].weight)` → `&rs[2]`.
