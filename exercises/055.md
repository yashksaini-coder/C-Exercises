# 055 — Decode big-endian bytes

Implement `uint32_t read_u32_be(const unsigned char *bytes)` in `055.c`.

`bytes` points at four bytes holding a 32-bit unsigned integer in
*big-endian* (network) order: the most significant byte comes first.
Return the value. `bytes[0]` is bits 31–24, `bytes[3]` is bits 7–0:

```c
(uint32_t)bytes[0] << 24 | (uint32_t)bytes[1] << 16 | (uint32_t)bytes[2] << 8 | bytes[3]
```

The cast matters. `bytes[0]` is promoted to `int`, and `int << 24` with a
byte of `0x80` or more overflows a signed 32-bit `int` — undefined
behavior. Cast to `uint32_t` *before* shifting.

Do not write `*(const uint32_t *)bytes` and swap afterwards. It is wrong
twice: the pointer may not be aligned to 4 bytes (a `SIGBUS` on ARM, SPARC,
and a slow trap on others; sanitizers flag it on x86 too), and it reads in
*host* order, which is little-endian on x86/ARM, so you would then need
`ntohl`. Byte-by-byte arithmetic has neither problem and the compiler
turns it into a single `bswap` anyway. Forbidden: `ntohl`, `memcpy` into a
`uint32_t` followed by a swap (the point is the arithmetic).

Examples: `{0x00,0x00,0x00,0x01}` → `1`; `{0x12,0x34,0x56,0x78}` →
`0x12345678`; `{0xFF,0xFF,0xFF,0xFF}` → `0xFFFFFFFF`;
`{0x80,0x00,0x00,0x00}` → `0x80000000` (the sign-bit case).
