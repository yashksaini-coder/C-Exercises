# 042 — Clone an array

Implement `int *array_clone(const int *values, size_t count)` in `042.c`.

Return a newly allocated array containing a copy of the first `count`
elements of `values`. The caller owns the result and frees it with `free()`.
Return `NULL` when `values` is `NULL` (and `count > 0`) or when allocation
fails.

Size the allocation as `count * sizeof *result` (or `sizeof(int)`), never
just `count`: the classic bug is `malloc(count)`, which allocates bytes, not
`int`s, and corrupts the heap on the fourth write. When `count` is `0` you
may return either `NULL` or a valid pointer that the caller can `free` —
both are acceptable, as with `malloc(0)` itself; the tests only exercise
`count > 0`.

Allowed: `malloc`, `memcpy`, or a plain loop. Forbidden: nothing specific,
but do not use `calloc` here (that is exercise 048).

Examples: `array_clone({1,2,3}, 3)` → a new array `{1,2,3}`, not the same
pointer; `array_clone({INT_MIN, INT_MAX}, 2)` → `{INT_MIN, INT_MAX}`;
`array_clone(NULL, 5)` → `NULL`.

> Read: Beej's Guide to C, §12.1 Allocating and Deallocating, `malloc()` and
> `free()`, and §12.3 The `sizeof` idiom for arrays —
> https://beej.us/guide/bgc/html/split/manual-memory-allocation.html
