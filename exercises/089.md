# 089 — Parse dotted-quad

Implement `bool parse_ipv4(const char *s, uint8_t out[4])` in `089.c`.

Parse an IPv4 address written as four decimal numbers separated by dots
(`"192.168.1.10"`) into four bytes, most significant first. Return `true` and
fill `out` on success. Return `false`, leaving `out` unspecified, when the
string is not exactly four octets: a missing or empty octet, an octet above
`255`, a non-digit character, or anything after the fourth octet (trailing
garbage, spaces, a fifth octet). Leading zeros are accepted (`"010.0.0.1"` is
`10.0.0.1`); this matches what `inet_pton` does.

Do it by hand: walk the string one character at a time with a running octet
value, and check for overflow *while* accumulating, not after (a long run of
digits such as `"99999999999"` must not wrap an `int`). No `inet_pton`,
`inet_aton`, `inet_addr`, `sscanf`, `strtol` or `atoi`.

Examples: `parse_ipv4("192.168.1.10")` → `true`, `{192, 168, 1, 10}`;
`parse_ipv4("0.0.0.0")` → `{0, 0, 0, 0}`; `parse_ipv4("256.1.1.1")` →
`false`; `parse_ipv4("1.2.3")` → `false`; `parse_ipv4("1.2.3.4.5")` →
`false`; `parse_ipv4("1..2.3")` → `false`.

> [!TIP]
> Read: Beej's Guide to Network Programming, §3.1 IP Addresses, versions 4
> and 6 — https://beej.us/guide/bgnet/html/split-wide/ip-addresses-structs-and-data-munging.html
> Interviewers like this one because the happy path is trivial and every
> boundary (empty octet, 255 vs 256, trailing text) is a separate bug.
