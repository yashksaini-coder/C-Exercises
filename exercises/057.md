# 057 — Host and network byte order

Implement `uint16_t my_htons(uint16_t value)` and `uint32_t my_htonl(uint32_t value)`
in `057.c`.

"Host to network short/long": return `value` converted from the host CPU's
byte order to network byte order (big-endian). On a big-endian host the
functions return their argument unchanged; on a little-endian host (x86,
ARM in its usual mode, RISC-V) they byte-swap. The results must equal the
real `htons`/`htonl` from `<arpa/inet.h>`, which the tests compare against.

Detect endianness *at runtime*, not with a preprocessor macro: write a
known 16-bit value and look at its first byte.

```c
static bool host_is_little_endian(void) {
    uint16_t probe = 1;
    unsigned char first;
    memcpy(&first, &probe, 1);   /* or: union { uint16_t u; unsigned char b[2]; } */
    return first == 1;
}
```

Swap with shifts and masks: 16-bit is `(value >> 8) | (value << 8)` (cast
the result back to `uint16_t`, since the `<<` promotes to `int`); 32-bit
moves each of four bytes to its mirror position. Because a swap is its own
inverse, `ntohs`/`ntohl` are the same functions.

Forbidden: `htons`, `htonl`, `ntohs`, `ntohl`, `__builtin_bswap*`,
`<endian.h>`/`<byteswap.h>`, and `#if __BYTE_ORDER__` checks — the point
is to see the machine decide at runtime. `memcpy` and unions are allowed
for the probe.

Examples (on a little-endian host): `my_htons(0x1234)` → `0x3412`;
`my_htons(1)` → `0x0100`; `my_htonl(0x12345678)` → `0x78563412`;
`my_htonl(1)` → `0x01000000`. On any host: `my_htons(0)` → `0`;
`my_htonl(0xFFFFFFFF)` → `0xFFFFFFFF`; `my_htons(my_htons(x)) == x`.
