# 038 — Unions and type punning

Implement `uint32_t float_bits(float value)` and `float bits_to_float(uint32_t bits)`
in `038.c`.

`float_bits` returns the 32 raw bits of the IEEE-754 single-precision
representation of `value`; `bits_to_float` is the inverse. A plain cast
`(uint32_t)value` would *convert* the number (`1.0f` → `1`), which is not
what you want: you need the bit pattern, `1.0f` → `0x3F800000`.

Use a union: `union { float f; uint32_t u; } pun;` Write `pun.f`, read
`pun.u`. All members of a union share the same storage, and C11 explicitly
allows reading a member other than the one last written (the bytes are
reinterpreted; C11 §6.5.2.3, footnote 95). This is called *type punning*.
Both `float` and `uint32_t` are 4 bytes here; `_Static_assert` that if you
like.

The other sanctioned way is `memcpy(&u, &f, sizeof u)`, which compilers
optimize to a single register move; it is also the only portable way in C++,
where union punning is undefined. What you must **not** do is
`*(uint32_t *)&value`: that violates strict aliasing and the optimizer may
silently break it. Do not call `frexp`, `ldexp` or any `<math.h>` function.

Examples: `float_bits(1.0f)` → `0x3F800000`; `float_bits(-0.0f)` →
`0x80000000` (negative zero has its own bit pattern); `float_bits(0.0f)` →
`0`; `bits_to_float(0x7F800000)` → `+INFINITY`; `bits_to_float(0x40490FDB)`
→ `3.14159274f`; `bits_to_float(float_bits(x)) == x` for every finite `x`.
