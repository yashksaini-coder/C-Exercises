# 065 — Generic binary search

Implement `void *my_bsearch(const void *key, const void *base, size_t count, size_t size, Comparator compare)`
in `065.c`.

`base` is an array of `count` elements of `size` bytes, **already sorted**
in the order defined by `compare`. Return a pointer to an element that
compares equal to `*key`, or `NULL` if there is none. The comparator is
always called as `compare(key, element)` — key first — so a comparator
written for `qsort` works unchanged. `count == 0` → `NULL`. **Do not call
`bsearch`.**

Return type is `void *` (not `const void *`) to match the standard: the
library returns a non-const pointer into memory the caller passed as
`const`, and the caller is responsible for not writing through it when the
array is actually read-only. Cast once at the end.

Use indexes, not pointers, for `low` and `high`, and compute the midpoint
as `low + (high - low) / 2`. The classic bugs: `high = mid - 1` when `mid`
is `0` underflows `size_t`, and `(low + high) / 2` can overflow. A
half-open range `[low, high)` sidesteps the first bug. Keep the search
O(log n): the tests cannot measure complexity, but an interviewer will.

Examples: key `7` in `{1, 3, 5, 7, 9}` → pointer to index `3`; key `4` →
`NULL`; key `1` (first) and `9` (last) → found; key `"kiwi"` in
`{"apple", "kiwi", "pear"}` with a `strcmp` comparator over `const char *`
elements → pointer to index `1`.
